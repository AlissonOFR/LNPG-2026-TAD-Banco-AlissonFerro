# LNPG-2026-TAD-Banco-AlissonFerro
Projeto acadêmico desenvolvido em Python com o objetivo de aplicar conceitos de Programação Orientada a Objetos. O sistema simula operações bancárias básicas, como cadastro de clientes, gerenciamento de contas, depósitos, saques e consultas de saldo, respeitando as regras de negócio definidas na especificação do trabalho.

Discussão

Durante o desenvolvimento deste projeto foram criados diversos subprogramas com o objetivo de organizar o código e evitar a duplicação de lógica. Entre eles estão as funções validar_nome, validar_cpf, validar_telefone, validar_email, validar_numeros_positivos e buscar_contas. As funções de validação foram criadas para centralizar as regras de negócio relacionadas aos dados informados pelo usuário, permitindo que diferentes partes do sistema utilizassem as mesmas verificações sem a necessidade de reescrever código. Já a função buscar_contas foi criada para localizar contas bancárias a partir de seu número, sendo utilizada em operações como consulta, remoção e verificação de duplicidade de contas dentro do banco.

Os relacionamentos entre Banco, Cliente e ContaBancaria foram implementados por meio da associação entre objetos. A classe Banco possui uma coleção de objetos ContaBancaria, representando o fato de que uma instituição financeira pode administrar várias contas simultaneamente. A classe ContaBancaria, por sua vez, possui referências para um objeto Cliente e para um objeto Banco, representando respectivamente o titular da conta e a instituição à qual ela pertence. Dessa forma, foi possível reproduzir os relacionamentos descritos na especificação do sistema de forma clara e organizada.

As regras de negócio que exigiram maior esforço de implementação foram as relacionadas à validação dos dados. A principal dificuldade encontrada foi na implementação da validação do CPF, pois foi necessário garantir que o valor informado não fosse nulo e possuísse exatamente onze dígitos numéricos, independentemente da presença de caracteres de formatação, como pontos e traços. Também foi necessário implementar validações para telefone, e-mail e números positivos, respeitando todas as restrições definidas na especificação do trabalho. Além disso, a regra que impede a existência de contas com números duplicados dentro do mesmo banco exigiu atenção especial durante o desenvolvimento.

Os conceitos de encapsulamento e abstração foram utilizados em toda a solução. A abstração foi aplicada na modelagem das entidades Banco, Cliente e ContaBancaria, representando elementos do mundo real por meio de classes. Já o encapsulamento foi empregado ao reunir dados e comportamentos relacionados dentro de cada classe, permitindo que as operações fossem realizadas por métodos específicos e mantendo a organização do sistema. Esses conceitos contribuíram para uma implementação mais modular, reutilizável e de fácil manutenção.
